# Native playback profiles and output policy

Native Playback treats Output Mode and Processing Profile as independent selectors. Direct Profile disables ReplayGain, EQ, and software volume changes and reports whether decoded and output parameters match; Processed Profile permits those transformations and labels the output accordingly. Changing software volume or enabling EQ while Direct is active switches to Processed with a brief notice. ReplayGain defaults off; enabling it once asks for album or track mode, stores that device-local choice, and shows whether the current file contains matching ReplayGain Metadata. The Music Server indexes that metadata so both Web and Desktop Clients can display it. Processed provides a ten-band graphic EQ with presets. Gapless playback uses mpv's weak mode so the Output Device can reopen when source parameters change rather than resampling later Tracks to the first Track's rate.

Linux exposes three output modes. System Output submits source parameters to PipeWire and observes what PipeWire selects. Direct ALSA Output opens a selected ALSA `hw:` device without PipeWire or ALSA conversion plugins; it does not use mpv's unsupported ALSA exclusive flag and may fail while the hardware is busy or reject an unsupported source format. The Desktop Client asks before falling back to System Output and remembers the choice for the current Playback Session. Experimental Adaptive System Rate temporarily forces the PipeWire graph to each source sample rate and resets the force setting when disabled, when the Desktop Client exits, or during recovery after an abnormal exit. If the Output Device cannot follow the graph rate, playback continues while Playback Telemetry reports device conversion. Compressed surround passthrough is excluded from the first native release because the Music Server does not currently index applicable formats.

## Consequences

The UI reports source codec, bitrate, bit depth, sample rate, and channels; decoded PCM format; PipeWire graph rate or bypass state; negotiated Output Device format; and active volume, ReplayGain, EQ, and resampling separately. The player bar shows a compact status that opens a Source → Decoder → System → Device → Processing detail view. It derives observable states such as `Format matched`, `Processed`, `Resampled`, and `Unknown`, but never displays an unprovable bit-perfect badge. The Web Client reports unavailable system and device values as `Browser managed / Unknown` rather than presenting source metadata as measured output. Adaptive System Rate requires an explicit warning and a reliable reset path because its effect is system-wide.
